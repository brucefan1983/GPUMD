:attr:`multi_replica`
=====================

This keyword selects replica-exchange molecular dynamics (REMD) or parallel replica dynamics (PRD).
Run the ``gpumd`` executable with a :ref:`run.in <run_in>` file containing this command.
The ``remd`` and ``prd`` parameters select the mode; their options are described on the following pages:

.. toctree::
   :maxdepth: 1

   multi_replica_remd
   multi_replica_prd

Syntax
------

::

  multi_replica <mode> replicas <number> [<per_gpu>] <options>

Parameters
----------

Select :ref:`remd <replica_remd>` or :ref:`prd <replica_prd>` and supply the corresponding options.
Each replica is a separate copy of the system.
To create a spatial supercell instead, use :ref:`replicate <kw_replicate>`.

``number`` is the total replica count.
The optional ``per_gpu`` is the capacity per GPU, defaulting to the replica count divided by the number of visible GPUs, rounded up.
Total capacity must accommodate all replicas.
Replicas are assigned round-robin and remain resident in GPU memory.
One process uses the visible GPUs on a single node; select GPUs with ``CUDA_VISIBLE_DEVICES`` or the job scheduler.

Output
------

REMD and PRD automatically write their :ref:`diagnostics and restart files <replica_output_files>`.
Trajectories require :ref:`dump_xyz <replica_kw_dump_xyz>`.
To continue a completed run, use the mode's ``resume`` option and preserve the complete set of :ref:`restart files <replica_restart>`.

Examples
--------

.. _replica_run_in:

With four visible GPUs, this places two replicas on each GPU::

  multi_replica remd replicas 8 2 exchange 1000 temp 300 450

A complete REMD input is::

  potential nep.txt
  time_step 0.5
  ensemble nvt_bdp 300 450 100
  multi_replica remd replicas 8 exchange 1000 temp 300 450 equilibrate 200000
  dump_xyz -1 0 5000 trajectory.xyz velocity
  run 2000000

This uses a geometric temperature ladder from 300 to 450 K, with 200000 equilibration steps followed by 2000000 production steps per replica.
See :ref:`replica_prd` for a complete PRD example.

Notes
-----

.. _replica_model_xyz:

Input files
^^^^^^^^^^^

Prepare :ref:`run.in <run_in>`, :ref:`model.xyz <model_xyz>`, and one supported potential file in the working directory, then run ``gpumd`` there.
All replicas use the same initial structure, species, masses, and simulation box.
REMD can optionally read a :ref:`temperature ladder file <replica_temperatures>`.

Initial velocities are generated by the replica driver; velocities in ``model.xyz`` are ignored for a fresh run.
A resumed run uses the velocities and random-number-generator states in its :ref:`restart files <replica_restart>`.

.. _replica_input_parameters:

Supported input commands
^^^^^^^^^^^^^^^^^^^^^^^^

A ``run.in`` containing ``multi_replica`` accepts only the commands below.
Specify ``multi_replica`` and ``ensemble`` once each, and put one ``run`` command last.
Other GPUMD commands, including ``deposit``, ``velocity``, and ``minimize``, cannot be combined with this mode.

.. _replica_kw_potential:

Potential
~~~~~~~~~

Use :ref:`potential <kw_potential>` with exactly one filename::

  potential <filename>

Energy NEP models and charge NEP (qNEP) models are supported.
Temperature-dependent NEP models are not supported.
Charge NEP models require periodic boundaries in all three directions.
GPUs are assigned whole replicas rather than spatial partitions of one system.

.. _replica_kw_time_step:

Time step
~~~~~~~~~

Use :ref:`time_step <kw_time_step>` with one positive time step in fs::

  time_step <dt>

The default is 1 fs. The optional maximum-displacement limit of ordinary MD is not supported in replica runs.

.. _replica_kw_ensemble:

Thermostat
~~~~~~~~~~

The :ref:`ensemble <kw_ensemble>` command must use ``nvt_bdp`` with a fixed simulation box::

  ensemble nvt_bdp <T_start> <T_end> <T_coup>

This is the stochastic velocity-rescaling thermostat of Bussi, Donadio, and Parrinello [Bussi2007b]_.
Temperatures are in K and must be positive.
``T_coup`` is the thermostat relaxation time divided by the time step and must be at least 1.

* REMD: the temperatures must match the ladder endpoints; they do not define a heating ramp.
* PRD: both temperatures must be equal.

The thermostat uses :math:`3N` degrees of freedom for REMD and :math:`3N-3` for PRD.
PRD removes center-of-mass motion and requires at least two atoms.

.. _replica_kw_kspace:

Electrostatics
~~~~~~~~~~~~~~

For qNEP models, :ref:`kspace <kw_kspace>` selects ``pppm`` (the default) or ``ewald``.
The optional PPPM mesh spacing has the same meaning and allowed range as in ordinary MD.
This setting has no effect for energy NEP models.
The method and an explicitly supplied spacing must match when :ref:`resuming <replica_restart>`.

.. _replica_kw_run:

Run length
~~~~~~~~~~

Use :ref:`run <kw_run>` once, at the end of ``run.in``, with a positive number of steps::

  run <number_of_steps>

* REMD: production steps per replica, excluding initial equilibration.
* PRD: correlation and parallel MD steps, excluding dephasing and minimization.
* Resume: additional steps beyond the saved state.

.. _replica_kw_dump_xyz:

Trajectory output
~~~~~~~~~~~~~~~~~

The optional :ref:`dump_xyz <kw_dump_xyz>` command can appear once and uses the following syntax in replica runs::

  dump_xyz -1 0 <interval> <filename> [velocity]

The interval must be positive. Only grouping method ``-1`` is supported; use ``0`` for the unused group index.
The filename cannot end with ``*``. Other ordinary-MD ``dump_xyz`` options are not supported.

* REMD: writes positions every ``interval`` production steps, with optional velocities.
* PRD: writes the initial quenched basin and each accepted transition.
  The interval is validated but ignored; use ``1``. Velocities are not supported.

See :ref:`replica_trajectory` for filenames and frame contents.
